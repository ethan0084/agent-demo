◆ 工作流（SOP）

单条作品入库的标准流程：识别 → 抓取 → 判断 → 分流 → 查重 → 写入 → 回报。
1

平台识别

只看链接域名：v.douyin.com → 抖音；xhslink.com / xiaohongshu.com → 小红书；都不是则停下询问。

2

抓取作品详情

调用数据接口获取作品标题、作者、点赞/收藏/评论/分享、发布时间等。可整段吞下分享口令，无需手动抠 URL。

3

作者归属判断

提取作者稳定标识（sec_uid / 抖音号），与账号表精确比对，绝不用昵称判断。

🔀 命中账号表 → 自家账号；未命中 → 对标账号
4

分流写入

自家账号 → 作品数据表（带关联账号）；对标账号 → 对标素材表（纯文本记录）。

5

查重

用作品 ID 查目标表：已存在 → 更新互动数据；不存在 → 新建记录。

6

回报结果

一句话说明三件事：进了哪张表、是否自家号、新增还是更新。

◆ 核心判断规则

Agent 在关键节点如何做决策。
场景规则
消息里只有分享链接直接入库，不反问
链接 + 在问问题先答问题，顺带问要不要入库
用户有明确其他意图按用户说的做，不写库
一条消息多个链接逐条处理、逐条回报
B站/视频号/YouTube 链接明确告知不支持，不硬塞
新增作品（抖音）必补播放量（列表接口恒为 0）
老作品不刷播放量；点赞增长 ≥30 才补一次（省 API 额度）
小红书播放量平台不开放，恒为 0，不显示不处理

◆ 能力边界

什么能做、什么不做、什么时候需要人。

✅ 擅长的事

  • 抖音/小红书分享链接自动入库与分流
  • 多账号每日增量同步与数据刷新
  • 日报/周报自动生成与多端推送
  • 账号粉丝/获赞/作品数周度跟踪
  • 历史数据本地存档与查档

❌ 不做的事

  • YouTube 下载与语音转写（已下线）
  • 小红书播放量（平台不开放）
  • B站/视频号等非抖音小红书平台
  • 翻页拉取全量历史作品（省额度）
  • 批量刷新老作品播放量（按次计费）

✋ 需要人工介入

  • 凭证缺失（API Key / 应用权限）需重新配置
  • 链接平台识别不出 → Agent 会停下询问
  • 对标账号需长期跟踪 → 人工加入账号表
  • 周报数据异常 → 人工核对表格
  • 批量补历史数据 → 需单独写一次性脚本
